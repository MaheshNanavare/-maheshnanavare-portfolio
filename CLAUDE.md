## What this is

Mahesh Nanavare's personal portfolio site. Next.js 16 (App Router) + React 19 + TypeScript + Tailwind v4, deployed on Vercel at `maheshnanavare.co.uk`. No CMS, no database, no MDX — content lives in typed TS files under `data/` and is edited directly.

See `PLAN.md` for the full design rationale, page breakdown, and a "Build notes" section documenting where the implementation diverged from the original plan (Next 16 instead of 14, Tailwind v4 CSS-based config instead of `tailwind.config.ts`, etc.) — read it before making structural changes.

## Architecture

- **All components except `Nav` are server components.** `Nav` (`components/Nav.tsx`) is the one `"use client"` component, because it uses `usePathname` for active-link styling. Don't add client components elsewhere without a real reason — this site intentionally ships almost no client JS.
- **Content is data, not markup.** Site copy (name, tagline, bio, roles, skills, nav links) lives in `data/site.ts`. Projects live in `data/projects.ts` as a `Project[]` typed by `types/project.ts`. To add a project: drop a screenshot in `public/projects/`, add one object to `PROJECTS`, push.
- **`liveUrl` is a required field on `Project`** (`repoUrl` is optional) — this is a deliberate enforcement mechanism so a project without a live deployment cannot be added without a type error. Preserve this constraint if you touch `types/project.ts`.
- **Tailwind v4 is configured in CSS**, not `tailwind.config.ts` — theme tokens (`--color-background`, `--color-accent`, etc.) live in an `@theme inline` block in `app/globals.css`.
- **Pages are thin.** `app/{about,projects,contact}/page.tsx` mostly compose existing components (`Hero`, `ProjectGrid`/`ProjectCard`, `SkillList`) over data from `data/`. `ProjectGrid` renders an explicit empty state when there are no projects yet — don't replace it with a generic loading/empty pattern.
- `lib/` is currently empty (kept from the original scaffold instructions); remove it if nothing ever lands there.

## Auth

Single hardcoded admin user via env vars — NextAuth v5 (`next-auth@beta`) with a Credentials provider, JWT sessions, **no database adapter**. `auth.ts` (repo root) checks the submitted email against `ADMIN_EMAIL` and `bcrypt.compare`s the password against `ADMIN_PASSWORD_HASH`. Route handler at `app/api/auth/[...nextauth]/route.ts`.

- **Route protection lives in `proxy.ts`, not `middleware.ts`.** Next 16 deprecated and renamed the `middleware` file convention to `proxy` (the export is `proxy`, not `middleware`). Every NextAuth v5 tutorial online still says `middleware.ts` — that file name silently does nothing here. It guards `/admin/:path*` and lets `/admin/login` through.
- **`/admin/(dashboard)/` is a route group** so the dashboard layout (with the logout button) wraps `/admin` but *not* `/admin/login`. The group parentheses keep the URL at `/admin`.
- **Escape every `$` in `ADMIN_PASSWORD_HASH` as `\$` in `.env`.** Next.js expands `$VAR` references in `.env` files, so a bare bcrypt hash (`$2b$10$...`) is silently truncated from 60 chars to whatever survives expansion, and `bcrypt.compare` then always fails with no useful error. Quoting does **not** help — only backslash escaping does. Verify with:
  `node -e "require('@next/env').loadEnvConfig(process.cwd()); console.log(process.env.ADMIN_PASSWORD_HASH.length)"` → must print `60`.
